name: auto-imagegen
description: Generate images for any OpenAI-compatible provider. Run --init once per machine to generate providers.json (auto-discovers Codex++/config.toml/auth.json/env), then generate images. Use when user asks to draw, generate, or create an image.
---

## Workflow

1. First run: `python "$SKILL_DIR/scripts/image_gen.py" --init`
   - Auto-discovers this machine's providers (Codex++ relay config, ~/.codex/config.toml, ~/.codex/auth.json, env vars) and writes `~/.codex/auto-imagegen/providers.json`.
   - Parallel probing (10s timeout each) picks the default provider/model. Use `--init --no-ping` to skip probing (offline).
2. Optional: `--inspect` to list providers and image models from providers.json.
3. Generate: `python "$SKILL_DIR/scripts/image_gen.py" "<prompt>"`
   - Uses `default_provider`/`default_model` from providers.json. Override with `--provider <name>` or `--model <id>`.
   - Images save to `<cwd>/generated_images/` (falls back to `~/.codex/generated_images/` when the cwd is not writable). Use `--out <path>` or `--img-dir <dir>` to change.
   - Default timeout 120s; use `--timeout <secs>` and set shell timeout_ms to at least 180000.
   - The generated image auto-opens in the default viewer. Use `--no-open` to disable.

## Per-Machine Setup (share this skill with anyone)

- Code is identical everywhere. Only `~/.codex/auto-imagegen/providers.json` is machine-specific — generated by `--init` on each machine.
- Works with OpenAI (auth.json login / OPENAI_API_KEY), Codex++ relay providers (agnes, cliproxy, DeepSeek, etc.), and any config.toml `[model_providers.*]` / env-var provider. No hardcoded vendors.
- The Codex++ aggregate relay port (127.0.0.1:57321) is always skipped.

## Output Format

| Line | Meaning |
|------|---------|
| `STATUS=SUCCESS` + `IMG_PATH=<path>` + `MODEL=<name>` | Image generated; reply with the path only (plain text) |
| `STATUS=FAILURE` + `REASON=<text>` | Generation failed; report REASON |
| `HINT=<text>` (stderr) | Suggestion on certain failures (e.g. wrong image API style, retry with --image-api chat) |
| `ERROR_DETAIL=<text>` (stderr) | Full API error details |

## CRITICAL: Never call view_image

Calling `view_image` embeds the full base64 image (~2-5MB) into conversation context, exceeding the context window and crashing the conversation. When you see `IMG_PATH=...`, respond with ONLY the plain text path. Never use ![alt](path), never invoke view_image. The generated image auto-opens in the default viewer (use `--no-open` to disable).

## Examples

```powershell
# First run on any machine (discovers providers, writes providers.json)
python "$SKILL_DIR/scripts/image_gen.py" --init

# Offline init (no probing)
python "$SKILL_DIR/scripts/image_gen.py" --init --no-ping

# See providers/models
python "$SKILL_DIR/scripts/image_gen.py" --inspect

# Generate with auto-selected default provider/model
python "$SKILL_DIR/scripts/image_gen.py" "A golden retriever in a park"

# Override provider/model, custom output
python "$SKILL_DIR/scripts/image_gen.py" "A cyberpunk city at night" --provider "agnes-ai" --model "agnes-image-2.1-flash" --timeout 180
```
